# ui

## Purpose

The local web UI (SP5 spec; system spec §9): a FastAPI app on `127.0.0.1` that serves the static screens, a JSON API over `ops` and a server-sent event stream of the journal. Needs the `[ui]` extra (`fastapi`, `uvicorn`).

## Interface

- `python -m super_harness.ui --port N`, token in `HARNESS_UI_TOKEN` (popped from the environment); started by `harness ui open` (`ops.ui_server`).
- `app.create_app(token=, port=)`: `GET /` (`?token=` sets an `HttpOnly`, `SameSite=Strict` cookie and redirects to `/`; otherwise 401 without it), `/static/*`, `GET /api/overview?window=today|7d|all`, `GET /api/board?project=`, `POST /api/pause|resume?project=`, `POST /api/tickets/{id}/approve|park|run|stop|merge|move` (body `{loops, tokens, why, to}`; each action reads what it needs), `GET /api/events` (SSE `event: journal` per new journal line, `: ping` every 15 s; `app.event_stream`). Harness errors come back as `{"error": …}`: 400, or 409 for setup and user decisions.

- `static/`: `index.html`, `fonts/` (Inter and JetBrains Mono latin woff2, `OFL.txt`), `icons.js` (the canvas's icons, `icon(name, {size, stroke, width, label})`, `STEP_ICONS`), `app.css` (the canvas tokens and step colours, dark scrollbars, `.select`, `.switch`, `.tabs-line`, `.foot-card`, `.pill`), `app.js` (sidebar with counts (tickets, agents on/total, broken links) and a live dot; each screen may export `top(data, app)` for its own top bar and `foot(data, app)` for its sidebar card, else the default top bar (project filter, search, `/to-ticket`, `/to-loop`) and none; `bind(root, app, data, bar)` gets the top bar too; hash routes; the nav follows the route before data arrives; refresh on journal events), `api.js`, `html.js` (templates that escape every value), `format.js`, `views/overview.js` (canvas board Main: tiles, live sessions in step colours with a two-click stop per row, approvals by gate kind with their action, token spend with the average ticket cost, the loop journal as one humanised line per event with Follow tail, the CLI pool as its sidebar card, and a banner while any folder link needs a fix), `views/board.js` (canvas board Board: its own top bar with project, importance and agent filters, a filter box, Board · List and `/to-loop`; running · blocked · done stats; Group by status, project or importance; full-height step-tinted columns with ⋯ (show as a list) and footers, shrinking to 156 px so seven fit beside the sidebar at 1440 px (more scroll sideways; a cut-off title shows whole on hover); cards with importance, parallel or serial, loop dots (wrapping under the badge on a narrow card), provider, chips, diff; a sortable List view; the importance legend as its sidebar card), `views/memory.js` (link health per project with Repair, Re-link and a two-click Adopt; stores found nearby). Other routes show a placeholder until M2.
- `GET /api/settings?project=` → `SettingsView` (empty `project` is the defaults); `POST /api/settings?project=` `{changes: {dotted.key: value|null}}` saves through `ops.configure` and answers with the new view.
- `scope.js`: `configBar(app, projects, setHere, {note, save, reset})` (the config top bar: scope select, overrides pill, note, Reset, Discard, Save), the configure screens' scope tabs, fields with set-here marks, Save · Discard · Reset (Reset and other destructive buttons act on a second click within 4 s); while a form has unsaved edits (`app.dirty`) journal events do not re-render it. `views/settings.js` (canvas board Settings): the config top bar (scope, overrides, Reset, Discard, Save), loop limits, token discipline, project commands (`project.test_cmd`, `project.lint_cmd`), status flow, SETTINGS.md coloured like the canvas with this scope's overrides in amber and both paths; a Memory section with file cards (MEMORY.md, PROCESS.md, DECISIONS.md, AGENTS.md), the shared store tree with ticket counts per folder, what the project sees through its folder link, and Re-link, Repair, Adopt a found store (second click) and Compact now.
- `GET /api/agents?project=&window=&refresh=&detect=` → `AgentsView` (`detect=0` runs no CLI: unchecked providers come back with `checked: false`); `views/agents.js` (canvas board Agents): scope tabs, Discard and Save in the top bar; provider cards (signed in, signed out, not installed, not supported; Sign in or Install copy the CLI's own command, harness never runs it) that fill in after the page renders, with Check sign-in again; the roster with switches, CLI · model, skill file, used-in bars per importance, tokens, and a pencil opening a row editor (CLI, skill, fallback list, blocking); limits and per-provider sessions; importance routing as each workflow's added steps.
- `GET /api/workflows?project=` → `WorkflowsView`; `graph.js` (`layout(steps, on_fail)`: trigger, steps, done top to bottom; `canvas(graph, {selected, sub, off, gate, ghost})`: 240×76 nodes on a dotted canvas with ports, pass edges labelled pass or signed off, send-back edges on lanes to the right labelled revise, findings or blocked, and a "not wired in" ghost step); `views/workflow.js` (canvas board Workflow): config top bar, importance tabs, toolbar (add node, auto-layout, dry run, zoom and fit), the selected step's agent, CLI · model, skill, send-back target, max loops, diff-only and session-reuse switches, move and remove, the node library, loop guard rails; a save writes each edited `workflows.<name>` whole plus any agent, loop or flag edits.
- `GET /api/tickets/{id}` → `TicketView`; `GET /api/tickets/{id}/diff` → the ticket's `Changes` with the diff; `GET /api/plans/{id}` → `{project, meta, sections}`. `views/ticket.js` (`#/ticket/<id>`, canvas board Ticket): a breadcrumb top bar and a sheet over the dimmed page that closes back where it was opened (×, Escape, or a click outside); header with importance, status pill, uuid, loop pill and the gate action; tabs Overview (prompt quote, plan on demand, scope, acceptance checkboxes, dependencies), Changes (files table, the chosen file's diff or the full diff, findings as severity cards), Timeline, Memory file (the ticket file with both paths, memory writes); a rail with the numbered agent chain, metadata, tags, attach, stop, send back, park with a why, and a two-click force move to done.
- `GET /api/memory?project=` → `MemoryView`; `POST /api/memory/compact` → `{started}` (`compaction.start_checked`; the screen refreshes on `memory.compacted`). `views/memory.js` (canvas board Memory): its own top bar (store or project, find, Verify links, Compact all), store tiles, the memory files table with the chosen file in a viewer (MEMORY.md shows its cap and last pass), link health as a list with a card and the one fix for each broken link, stores found nearby with a two-click Adopt, the ticket index with All · Running · Done and model chips, writes to memory, and the backends as its sidebar card.
- `GET /api/meta` → `{version}`. `GET /api/links` (link health); `POST /api/links/repair` (`harness doctor --fix`), `POST /api/links/relink` `{project, path}`, `POST /api/links/adopt` `{path}`; each answers with the new link health.

## Invariants

- Imports only `ops` and `model` (import-linter); every action goes through `ops` with `by="ui"`.
- No network fetches, no build step: the screens are static ES modules and one stylesheet.
- `/static/*` answers with `Cache-Control: no-cache`, so an upgraded harness shows its new screens at once.
- The sign-in cookie is named per server (`harness_token_<port>`): cookies ignore ports, so two UIs on one machine keep their own sign-in.
- The journal stream closes on `pagehide` and reopens on `pageshow`, so stale tabs never hold one of the browser's few connections to the server.
- Below 860 px the sidebar becomes a scrolling top nav and gutters shrink to 16 px; a failed load shows what went wrong and a way back.
- Every `/api` request needs the run's token; foreign `Host` and `Origin` headers are refused (system spec §10); `POST` needs `X-Harness: 1`.
