# ops

## Purpose

Use cases shared by the CLI and the UI. Each function takes plain arguments, works through `store`, `model` and the `settings`, `memory` and `journal` units, and returns a dataclass the caller formats.

## Interface

- `stats.compute(paths, project, days)` → `Stats(minutes, merged, first_pass, tokens, models, gates)`, from the journal (SP20 spec §3.4); `agents.pick(..., loop=)` puts `escalate` first from loop 2.
- `merging`: a rebase conflict is replayed and settled (`_settle`): generated files regenerate, anything else goes back to implement at no loop cost; `checks.generate_request`; `hygiene` treats 250,000 and 1,000,000 as old token caps; `steps._freshen` rebases a moved base before review (SP19).
- `harvest` (SP18 spec §3): `submit` queues text and starts the job, never raising; `run_harvest` drains the spool; `from_hook` reads a Claude Code hook; `read_chat`; `queue_plan`. `tickets.check_batch`; `queue.stuck`; `skills.install_hooks`.
- `projects.init_project(path)` → `InitResult`: registers the repo containing `path`, seeds its store folder, links `<repo>/.kengash`, adds the exclude entry. Idempotent.
- `projects.relink(slug, new_path)` → `InitResult`: re-points a moved project.
- `projects.doctor(fix, scan)` → `DoctorReport`: one `Problem` per repo, folder link, memory link (`projects/<slug>/memory -> ../../memory`; a real folder there is reported, never replaced), exclude or document issue, then repo trust, ignored store copies of built-in skills (one warning per roles folder), old kengash skill names in each repo and the home folder (a warning), and provider checks; `fix` repairs links and exclude entries only. `Problem.warning` marks findings that never fail `doctor`.
- `slots`: `queue_slot` (a claim queues its first slot), `acquire` (a worker's waiter is granted once every earlier waiter that fits has been), `release`, `occupied` (held plus queued, for claims), `limits` (defaults scope and each project), all under `slots.lock`.
- `agent_config` (SP6 spec decisions 5-7, SP10 spec §4): `new_agent(role, kind=, does=, cli=, step=, workflows=, after=, send_back=, fallback=, skill=, instructions=, project=, by=)` (a `skill` or the agent's own `instructions`, not both; neither: the kind's starter) → `AgentChange(project, role, step, keys, skill_file)`: refuses a role or step that exists and `send_back` on a non-review step, inserts the step into each named workflow after `after` (default: before `approve`, else last) with a review step's `on_fail` edge (default `implement` when present), writes `agents.<role>`, `steps.<step>` and each `workflows.<name>` whole reading the settings and writing them in one validated `settings.set_values` save under `settings.lock`, then a starter `roles/<role>/SKILL.md` per kind in the scope unless `skills.role_file` finds one; journals `settings.changed` and commits `kengash: agent new <role>`. `remove_agent(role, project=, by=)`: refuses built-in roles, a role this scope's file does not set, and a step an `in_process` ticket of the scope sits at; removes the agent, its steps, their workflow entries and `on_fail` edges; the skill file stays.
  `edit_agent(role, AgentPatch(cli, fallback, on, blocking, bypass_permissions, kind, does, skill, instructions), project=, by=)`: a built-in agent refuses `kind`, `does`, `skill` and `instructions` (`<role> is a built-in agent; its <field> is fixed; copy it to change what it does`); a kind leaving `review` drops that step's `on_fail` edges in one save. Own instructions go to the scope's `roles/<role>/SKILL.md` under a generated header (`HEADER`, `metadata: {source: user}`), refused when empty or over `instruction_caps(role, caps)` (the skill caps less the header). `show_agent(role, project=)` → `AgentDetail` (`kengash agent show`). `copy_agent(source, new, project=, by=)`: a user's agent with the source's kind, CLI, fallbacks, description and skill text (not the test runner). `describe(paths, resolved, project, role)` → `AgentDetail(role, builtin, kind, step, does, cli, provider, model, fallback, on, blocking, bypass_permissions, skill, instructions_own, instructions, used_in=[UsedIn(workflow, position)], tokens)`; built-in descriptions are `BUILTIN_DOES`.
- `configure` (SP5 spec decision 7): `save_settings(changes, project=, by=)` → `Saved(project, keys)`: under `settings.lock`, `settings.set_values` on the defaults (`project=None`) or one project, then `settings.changed` (`keys`, `by`) and a store commit `kengash: settings <scope>`; a save that changes nothing journals nothing.
- `workflows` (SP10 spec §4.5-4.6): `new_workflow(name, from_=, project=, by=)` (a copy, or `steps: [implement]`), `rename_workflow(old, new, …)` (routing that named it follows), `remove_workflow(name, …)`, `route(importance, workflow, …)`, `set_workflow(name, steps, on_fail, …)` → `WorkflowChange(project, name, keys)`, each one validated save under `settings.lock`, journaled `settings.changed` and committed. Rename and remove refuse a workflow the package ships (`ships with kengash; edit its steps instead`), one not set in this scope, one a project sets or routes to (defaults scope), one an importance routes to (remove), and one an open ticket runs, naming the tickets.
- `ui_server` (SP5 spec decisions 2 and 3): `open_ui(browser=)` → `UiServer(url, pid, port, reused)` (reuses a live server from `runtime/ui.json`, else starts `python -m kengash_ai.ui` detached on a free port with a fresh token and waits up to 10 s, killing a server that stays silent; `NeedsSetup` naming the install line without the `[ui]` extra), `stop_ui()` (SIGTERM to its group), `has_extra()`.
- `views` (SP5 spec §3): read models for the UI, built from the store, runtime and journal, writing nothing. `overview(paths, window=)` → `Overview(projects, paused, tickets_total, grant, avg_loops_done, avg_ticket_cost, agents_on, agents_total, sessions, queue, gates, done_today, slots, spend, conductors, tail, loops, auto_default, auto)` (`loops`: live `loops.LeaseView`s; `auto_default` and `auto` per project: `loop_start` is `auto`; SP11) (sessions are in_process tickets running a step; parallel-safe tickets name `touches`; spend sums `step.end` tokens per provider in the window); `board(paths, project=)` → `Board(columns, steps)`: in queue, each step column (plan, implement, code review and security always; plan review, tests, docs and approval once a ticket is there; a column per custom step the scope's workflows use, or that holds a ticket, placed after the step its first workflow runs before it, titled from its name), done; a ticket at a gate or waiting stays in its step's column (with no step: its workflow's last) and its `Card.chip` says why (loop cap hit, stalled, failed, waiting slot, ready to merge, blocked, parked…); cards also carry `rejected` (failed plan reviews), `done_at`, `tags`; `Column.footer` names the step role's live sessions, `· blocking gate` for a blocking security reviewer, and the implementer's slot use; `steps` counts each workflow's steps; both default to the user's store. `links(paths, nearby=)` → `Links(projects, nearby, intact, total)`: per project a `ProjectLink` (folder link state, memory link state, exclude entry, tickets, and the one `fix`: `repair` → `kengash doctor --fix`, `relink` for a moved repo, `adopt` for a real `.kengash/` folder, `manual`), and `FoundStore`s, real `.kengash/` folders up to two levels below the folders that hold registered repos; `Overview.links_broken` counts projects needing a fix. `settings_view(paths, project=)` → `SettingsView(scope, projects, values, set_here, file, path, repo_path, problem)` (resolved values, the scope's overrides, its SETTINGS.md and both paths of it; an invalid file comes back with `problem` and no values). `agents_view(paths, project=, window=, refresh=, detect=)` → `AgentsView(scope, projects, providers, agents, skills, instruction_caps, sessions_max, tokens_per_ticket, fallback_on_error, per_provider, set_here, problem)` (SP10: `agents` are `agent_config.describe` details with `step.end` tokens of the role in the window, `skills` the `SkillRef(name, source)` an agent may run from `skills.role_skills`, `instruction_caps` the lines and words own instructions may hold; each card also lists the CLI's `models`): a `ProviderCard` per provider (install and sign-in from `agents.detector`, kept for 60 s per process unless `refresh`; with `detect=False` nothing runs and providers not yet detected have `checked=False`; slots held and allowed; spend in the window) and a `Role` per agent (CLI split into provider and model, skill file, workflows using it, `step.end` tokens of that role in the window, `custom` for a user's role, the custom `step` it runs and that step's `does`). `workflows_view(paths, project=)` → `WorkflowsView(scope, projects, names, workflows, effective, warnings, loop_max, loop_ask_at_cap, agents, skills, off, plan_review, review_diff_only, sessions_reuse, blocking, library, roles, kinds, does, routing, picker, set_here, problem)` (SP10: `routing` maps each importance to its workflow, `picker` lists a `PickAgent(role, step, kind, builtin, on)` per insertable step, `approve` as the user): each workflow as written, every usable step (built-ins, then custom) with its role, kind and a custom step's instruction, the steps a ticket would run (`workflow.steps_for`), a warning when a blocking role is off. `ticket_view(paths, ticket_id, project=)` → `TicketView(project, meta, sections, file, store_path, repo_path, plan, siblings, depends_on, blocks, changes, timeline, memory_writes, chain, attach, grant)`: the plan's title and prompt (`found` false when the plan file is gone), `TicketLink`s to siblings (same plan), dependencies and the tickets it blocks, `ops.changes` rows (empty without commits), a `TimelineStep` per `step.end` and status event, `memory.write` events that name the ticket, a `ChainStep` per workflow step (`done`, `running`, `waiting`, `needs you`, `pending`, with its runs), the attach command (empty without a session) and `loop_grant`. `memory_view(paths, project=)` → `MemoryView(project, size_bytes, ticket_files, tickets, links, files, memory_text, cap, compacting, last_before, last_after, index, writes)`: store size without `.git`, worktrees and runtime; tickets per folder; `MemoryFile`s for MEMORY.md and DECISIONS.md, plus the project's PROCESS.md, SETTINGS.md and its repo's AGENTS.md when `project` is given (lines, `- ` entries, characters / 4 per read, last accepted compaction, mtime, text); an `IndexRow` per ticket (provider/model of its steps, when it closed); the last 30 `memory.write`, `memory.compacted` and `ticket.moved` events, newest first. `journal_end()`, `events_after(cursor)` feed the UI's event stream; `version()`. Views keep each parsed journal day per process and parse a day file again only when its size or mtime changes.
- `evals` (SP4 spec decisions 11 to 13): `load(path)` (a problem names the file), `scenarios(root, skill)` (`<skill>/<scenario>` names), `fill(text, values)` (`{name}` placeholders), `agent_values(agent, model)` (`{agent}`, `{model}`, `{cli}`, and `{kg}`: `/kengash:` on claude, `$kengash-` on codex, `/kengash-` on antigravity, whose evals install copies; filled into settings, setup and turns). `run_scenario(name, scenario, agent, work=, model=, baseline=, source=)` → `EvalRun(name, agent, passed, failure, work)`: a scratch repo and store under `work`, `kengash init`, settings, setup commands (`save` keeps the first 8-hex word), the skills installed for the agent (none with `baseline`), each turn through `conductor_argv` (claude `dontAsk` with `Bash(kengash:*)` and `--plugin-dir` on the installed plugin, since `-p` skips project plugins; agy `--output-format stream-json` with `--settings` allow-rules (`AGY_ALLOW`: `command(kengash)`, `ls`, `pwd`, `git status|diff|log`, `read_file(*)`) and a workspace `AGENTS.md` (`AGY_RULE`) saying so, since a denied command ends a headless agy turn; no sandbox, whose read-only `~/.gemini` stopped every agy kengash starts; codex bypass, documented only) resuming the session (`parse_turn`), leftover workers stopped, then `check`: the first missed expectation names itself (`clean` also fails on files the turns changed in the repo). `run_evals(skill, agents_=, model=, baseline=, root=, keep=)` → `(runs, folder)`: every scenario on each agent (named ones must be usable, `NeedsSetup` otherwise; by default every usable agent), on its cheapest model unless `model`. UI scenarios (SP5 M3): the conductor's environment sets `BROWSER=true` so `kengash ui open` opens no window, `ui: true` needs the sandbox store's UI server running, and any UI server a run leaves is stopped.
- `skills` (SP4 spec decisions 2, 3, 7): `ROLES`, `roles_dir()`, `role_file(paths, slug|None, skill)` (a built-in skill: always the package's file; a user's: the project's, else the defaults'), `ignored_copies(paths)` (store copies of built-in skills, never read), `role_text`, `packaged()` (the installed skills: the package's `skills/`, else the checkout's), `lint(targets, commands=, caps=)` → `Problem(path, message)` items (installed skills: frontmatter, name, "Use when" and 500 characters, caps, step 0, references, known commands; role skills in a `roles` folder: frontmatter, name, caps), `lint_skills` (default targets and the user's caps), `mentions(body)` (the command words of each `kengash` code span or fenced line), `install(agents, root=, home=, cli_name=, yes=, source=, agy_plugin=, user_home=, run=)` → `InstallResult(entries, diffs)` with `needs_yes` (SP10 spec §3.2: claude gets the `kengash` plugin folder `.claude/skills/kengash/` with `.claude-plugin/plugin.json` and `skills/<name>/`; antigravity gets the plugin built in a temporary folder and `agy plugin install`ed, skipped when `~/.gemini/config/plugins/kengash/` already holds the same files, else `kengash-<name>` copies noted `agy plugin install failed; copies instead`, as when `agy_plugin` is off; codex gets `kengash-<name>` copies in `.agents/skills`; globally `~/.claude/skills`, `~/.agents/skills`, `~/.gemini/config/skills`; copies are renamed and spell commands `$kengash-<name>` (Codex) or `/kengash-<name>`; a skill folder swapped in whole; one that differs is replaced only with `yes`, else its unified diff is returned; our old-named skills are removed), `plugin_manifest()` (name `kengash`, version, author, description, homepage, license), `install_skills` (the repo containing a path, or the home folder), `home_folder()`, `old_installs(roots)` → `(folder, agents)` for each `.claude/skills`, `.agents/skills` or `.gemini/config/skills` under the roots that holds our skills by a pre-SP10 name, `rename_cli(text, name)` (command prefixes in code spans and fenced lines only). `show(name, agent=, cli_name=)` (SP11): a packaged skill rendered as `install` would for that agent (`spelling_for(agent)`: `$kengash-` for codex, else `/kengash:`), without frontmatter, each `references/<file>` appended as `## references/<file>`; `invoked_name(argv0)`: `kengash` when this CLI is the first on PATH, else its full path.
- `jobs`: detached job workers (SP3 spec decision 33). `spawn` (`python -m kengash_ai.worker <args>`, new session, `runtime/logs/<name>.log`), `start` (spawn and save the record), `alive` (live pid and fresh heartbeat), `end` (SIGTERM to a running worker's process group, SIGKILL after 10 s, then drop its record; False when none runs), `heartbeat`, `forget` (own pid only), `exited` (`worker.exited` with `job`, `ok: false`, `reason`), `await_event` (the first matching journal event after a cursor; a synthetic `worker.exited` once the worker is gone; None at the timeout), `take_slot` (polls every 5 s, heartbeating), `died` (free the slot, journal "worker died"). `COMPACT` is the compaction job's id; plan reviews use the plan id.
- `calls.call(paths, provider, request, next_log)` → `Called(request, result, usage)`: the retry rules every CLI call shares (a timeout retries once; a schema error, and an empty turn whose actions were denied, get one repair turn on the session; `denied(result)` words it); `calls.again`, `repair`, `failure`, `plus` and `step_timeout` serve ticket steps too.
- `steps.run_job(ticket_id, project=, steps=)` → `JobEnd(status, reason)`: the step loop of SP3 spec §5. Per step: flags and caps under the project lock (`workflow.before`), the agent (`agents.pick`), a slot (`waiting_slot` while queued), the session (reused per role and provider; claude ids chosen before the call), the prompt, one adapter call, a commit with trailers after editing steps (agent commits folded by `reset --soft`), then Handoff or Findings, Log, tokens, session, `step.end`, routing (`workflow.after`) and a store commit under the lock. `steps=N` pauses after N steps. Errors: `timeout` retries once; `schema` gets one repair turn on the session; `rate_limit` and `network` fall back (`fallback_on_error`; `network` first resumes once) or waits as `waiting_quota` until `retry_after` (15 minutes when unknown); `auth` fails with "sign in to <cli> interactively"; others fail with the log path. A failing commit hook gets one repair turn. A ticket the user moves mid-step keeps its status; the result is dropped. A dead worker's `running` call gives its session back (`recover_session`). A retried new claude session resumes once claude reported it or it timed out; one that never started is forgotten, so the next run starts afresh. `steps.fail_ticket(paths, slug, id, reason)` fails a running ticket; `fail_job` serves the worker.
- `calls.call(paths, provider, request, next_log)` → `Called(request, result, usage)`: a timeout retries once (a new claude session the CLI reported, or that timed out, is resumed), a schema error gets one repair turn on the session, anything else returns; `again`, `repair`, `failure`, `plus` and `step_timeout` serve `steps` too.
- `controls.run_tickets(ids, steps=, project=, by=)` → `RunResult(started, skipped)`: under the project lock, a live worker, the status (`in_queue/ready` or `in_process/failed|stalled|paused`), a pause, `touches` overlap, the first step, the agent (`NeedsSetup` when nothing usable) and a slot (`slots.reserve`) are checked; a claim creates or reuses the worktree (under `repo-<slug>.lock`), sets step and status, starts `python -m kengash_ai.worker` (`spawn_worker`) and writes its record. Resuming a stalled ticket clears its stall streaks and plan-review rounds. An approve step waits for `kengash approve` without a worker. A network-less codex sandbox → `NeedsSetup`.
- `controls.approve_ticket`, `park_ticket` (deferred while a worker runs), `stop_ticket` (`jobs.end`, then failed "stopped"), `pause`, `resume`.
- `merging.merge_ticket(id, project=, by=)` → `Merged(id, project, commits, base)`: from `awaiting_merge` or `branch_ready`, under the project lock and `repo-<slug>.lock`: rebase in the worktree (a conflict writes a finding and sends the ticket to `in_queue/ready` at `implement` with loop + 1, or to `needs_approval` at the loop cap, exit 1), `git merge --ff-only` in the main working tree (refused when dirty or off base), remove the worktree and branch, `done/merged`, dependents turn ready. `merging.merge_if_clean` serves `merge.mode: auto` (called after the project lock is released).
- `waiting.wait(project, timeout=, poll_s=)` → `WaitResult(events, idle, timed_out)`: the first call per scope reports the open gates (its cursor saved first); later calls report gate events from the journal after the scope's cursor (`ticket.needs_approval|stalled|failed|awaiting_merge|merged`, moves into `done/`, and `plan.reviewed` as `kind: plan`; a ticket added or moved to `in_queue/ready` as `queued`, its title the detail, SP11), first holding the loop lease (a detected agent claims it, any other caller only checks; both raise `LoopBusy` under another conductor's live lease), `idle` when nothing in scope runs (a live worker in scope counts, and it is checked before the journal read, so a gate a finishing worker journals is never lost to `idle`), or `timed_out`. Reviewed plans awaiting approval are open gates. `waiting.check_workers(paths, fix=)` fails the tickets of dead workers (gone pid or heartbeat older than 2 minutes) "worker died" and drops dead plan-review and compaction jobs (`jobs.died`); `dead_workers` lists their records; `ping` records the conductor. `conductors.conductor()` → `Conductor(pid, agent, command, detected)`: the nearest ancestor named claude, codex or agy (`detected`), else the parent; `agent` is `$KENGASH_AGENT`, then `$HARNESS_AGENT`, then the detected name; `process_name(pid)` (SP11). `leases` (SP11 spec §4): `claim(paths, project, me, take_over=)` → True when new or rescoped (journals `loop.started`; drops leases that are not live as `gone`; another conductor's live overlapping lease raises `LoopBusy`, or is `taken_over`), `check`, `refresh` (seen now; never recreates a lease taken over), `live(paths)`, `is_live` (pid alive under its recorded name, seen within `LOOP_STALE_S` = 3600 s), `overlaps`, `describe`, `scope_name`, `own_lease`, `ended`, `guarded(paths)` (`locks/loops.lock`). `next` checks workers and pings; `doctor` reports dead workers and marks them with `--fix`.
- `changes.ticket_changes(id, diff=, project=)` → `Changes(id, project, ref, changes, diff)`: one `Change(path, added, removed, loop, step, model, commit)` per file and commit, from the `Harness-*` trailers, on the ticket branch or (once merged) the base branch. `changes.attach_command(id, role=, project=)` → `Attach(..., command)`: `cd <worktree> && <the CLI's resume command>`.
- `lifecycle`: `step_status` (the `status.names` sub-status), `status_event` (the journal event of a status, with `status`, `loop`, `loop_max`, `reason`), `progress_of` (moved from `queue`), `progress_for` and `apply_progress` (workflow progress to and from a ticket and its state), `pid_alive`, `DEAD_AFTER_S`.
- `slots.reserve`: a claim's check and queueing under one lock.
- `tickets.refresh_queue` (was private): turn queued tickets ready or blocked to match their dependencies.
- `checks` (SP15): `wanted(resolved, ticket, step)` (fix turns on, a command set, and an enabled `check`-kind step after `step`), `request(resolved, worktree, log)` (the shell request), `outcome(result)` (verdict `pass`, `fail`, `timeout` or `error`, and summary). `steps._verify` runs them after an editing step's reply and, while they fail and `checks.turns` remain, resumes the session with `prompts.fix_prompt` (`network` resumes once, `schema` or `empty` keeps the last valid reply, other errors fail the ticket); each run writes `## Check output`, a `checks` Log line and `checks.end`, and names itself in `state.running`; a moved ticket ends the checks. After the commit, checks whose last run passed (and no commit-hook repair turn after them) become `TicketState.checked`; a shell `check` step on that same commit with a clean worktree passes from it (`<summary> (in <step>, same commit)`) without running (`steps._reused`).
- `prompts`: step instructions, `new_prompt` (role, step, Goal, Scope, Acceptance, Handoff, Findings, diff stat inline), `resumed_prompt` (Findings for work steps; Handoff and diff stat for review steps), `repair_prompt`, `handoff_text` (redacted, 15 lines), `findings_text`, `log_line`, `kind`, `output_kind` (review and check steps `review`, read steps `plan`, edit steps `work`; SP16), `profile` (by the step's kind, custom steps included when given the settings), `instruction` (a built-in step's line, or a custom step's `does` plus its kind's rule), `role_skill` (`skills.role_text`: a built-in skill from the package, a user's from project `roles/<role>/SKILL.md`, then `defaults/roles/`; the body without frontmatter), `plan_review_prompt` (the plan inline; a new session also gets the memory digest, a resumed one the Review log), `review_log_lines`, `compact_prompt`. SP15: `Feedback` (checks, sent-back line, user answer, editing) given to `new_prompt` and `resumed_prompt` adds `## Check output` (editing steps) and `## Checks`; a sent-back line replaces a resumed step's instruction, the user's answer follows it; `checks_block`, `sent_back_line` (flat, redacted, summary ≤ 300), `fix_prompt`, `check_log_line`. `steps._feedback` builds it from the settings and `TicketState.sent_back`.
- `reviews` (SP3 spec decisions 14, 28 to 30): `conductor_provider(by)` (`--by`, else claude under `CLAUDECODE=1`), `choose_reviewer(settings, conductor, detect)` → `(Pick, warning)` (a named `plan.reviewer`; else the plan-reviewer chain without the conductor's provider, then any other usable provider, then the conductor's own with a warning), `review_plan(plan_id, project=, by=, timeout=)` → `ReviewRound(id, project, round, max, verdict, findings, reviewer, warning)` with `used_up` (attach to a running round, reprint a round with its verdict, or choose the reviewer, mark the plan `in_review`, start the job and wait for its `plan.reviewed`; `NeedsUser` once the rounds are used up, `WaitTimeout` while it runs on), `run_review(plan_id, project=)` (the `plan-review` worker's round: read-only in the repo, a slot, the reviewer session resumed per plan and provider, round, verdict, session and Review log written, `plan.reviewed` journaled; a failed call or a plan changed meanwhile journals `worker.exited` instead), `fail_review`.
- `compaction` (SP3 spec decision 31): `start_checked()` → True once the job runs (the UI's Compact: `NeedsSetup` when the compactor's CLI cannot run, a running job is left alone), `compact_memory(timeout=)` → `memory.Compaction` (start the `compact` job or join it, then wait for `memory.compacted`; `NeedsSetup` when the compactor cannot run, `UserError` when the job fails, `WaitTimeout`), `start_background(paths)` (from `workspace.remember` once MEMORY.md passes its cap), `run_compaction()` (the worker's job: `memory.compactor`, read-only in `memory/`, a new session, a slot; `memory.apply_compaction` checks and writes), `fail_compaction`.
- `agents.pick(settings, role, status, skip=)` → `Pick(role, provider, model, fallback)`: the role's `cli`, then each fallback, first usable; `NeedsSetup` naming the install or sign-in step when none is. `agents.detector(paths)` detects each provider once; `agents.problem(provider, status)` says why one cannot run.
- `providers.check_providers(paths)` → `ProviderCheck(provider, users, blocking, message)` for each provider that enabled agents, their fallbacks or the compactor need (all scopes) and that is missing, signed out or unsupported (`blocking` when a role or the compactor is left with no usable provider), plus a warning for a claude login other than claude.ai unless `providers.claude.allow_api_key`; scopes with invalid settings are skipped. Detection goes through `adapters`.
- `providers.cli_clash()`: a warning when the first `kengash` on PATH is not Kengash AI (its `--version`), suggesting `--cli-name` with this one's full path; `doctor` reports it.

## Invariants

- Registry changes happen under `runtime/locks/registry.lock`; project, plan and ticket changes under `runtime/locks/<slug>.lock`, then journal events, then a store commit.
- Every state change ends with a store commit (`kengash: <command> <slug>`).
- Adopt deletes nothing: the original folder and every losing copy end up in `projects/<slug>/archive/adopted-<stamp>/`.
- `ticket add` validates the whole batch (schema, keys, references, cycles, workflows) before writing any ticket; a ticket is `ready` only when every dependency is merged or closed (`done/branch_ready` keeps dependents blocked).
- Queued tickets stay consistent: after any move or `depends_on` change each `ready`/`blocked` ticket is re-derived from its dependencies; `parked` is left alone; `in_process` needs every dependency merged or closed; a move to `done` clears the ticket's `step`, while parked or requeued tickets keep it and resume there.
- `ops` never imports `cli` or `ui`.
