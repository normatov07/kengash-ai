# ops

## Purpose

Use cases shared by the CLI and the UI. Each function takes plain arguments, works through `store`, `model` and the `settings`, `memory` and `journal` units, and returns a dataclass the caller formats.

## Interface

- `projects.init_project(path)` → `InitResult`: registers the repo containing `path`, seeds its store folder, links `<repo>/.harness`, adds the exclude entry. Idempotent.
- `projects.relink(slug, new_path)` → `InitResult`: re-points a moved project.
- `projects.doctor(fix, scan)` → `DoctorReport`: one `Problem` per repo, link, exclude or document issue, then repo trust and provider checks; `fix` repairs links and exclude entries only. `Problem.warning` marks findings that never fail `doctor`.
- `slots`: `queue_slot` (a claim queues its first slot), `acquire` (a worker's waiter is granted once every earlier waiter that fits has been), `release`, `occupied` (held plus queued, for claims), `limits` (defaults scope and each project), all under `slots.lock`.
- `ui_server` (SP5 spec decisions 2 and 3): `open_ui(browser=)` → `UiServer(url, pid, port, reused)` (reuses a live server from `runtime/ui.json`, else starts `python -m super_harness.ui` detached on a free port with a fresh token and waits up to 10 s; `NeedsSetup` naming the install line without the `[ui]` extra), `stop_ui()` (SIGTERM to its group), `has_extra()`.
- `views` (SP5 spec §3): read models for the UI, built from the store, runtime and journal, writing nothing. `overview(paths, window=)` → `Overview(projects, sessions, queue, gates, done_today, slots, spend, conductors, tail)` (sessions are in_process tickets running a step; parallel-safe tickets name `touches`; spend sums `step.end` tokens per provider in the window); `board(paths, project=)` → `Board(columns)` with one `Column` per status group and `Card`s carrying loop, provider, diff size and finding count; both default to the user's store. `journal_end()`, `events_after(cursor)` feed the UI's event stream.
- `evals` (SP4 spec decisions 11 to 13): `load(path)` (a problem names the file), `scenarios(root, skill)` (`<skill>/<scenario>` names), `fill(text, values)` (`{name}` placeholders), `agent_values(agent, model)` (`{agent}`, `{model}`, `{cli}`, filled into settings, setup and turns). `run_scenario(name, scenario, agent, work=, model=, baseline=, source=)` → `EvalRun(name, agent, passed, failure, work)`: a scratch repo and store under `work`, `harness init`, settings, setup commands (`save` keeps the first 8-hex word), the skills installed for the agent (none with `baseline`), each turn through `conductor_argv` (claude `dontAsk` with `Bash(harness:*)`; agy `--dangerously-skip-permissions --sandbox`; codex bypass, documented only) resuming the session (`parse_turn`), leftover workers stopped, then `check`: the first missed expectation names itself (`clean` also fails on files the turns changed in the repo). `run_evals(skill, agents_=, model=, baseline=, root=, keep=)` → `(runs, folder)`: every scenario on each agent (named ones must be usable, `NeedsSetup` otherwise; by default every usable agent), on its cheapest model unless `model`.
- `skills` (SP4 spec decisions 2, 3, 7): `ROLES`, `roles_dir()`, `role_text`, `packaged()` (the installed skills: the package's `skills/`, else the checkout's), `lint(targets, commands=, caps=)` → `Problem(path, message)` items (installed skills: frontmatter, name, "Use when" and 500 characters, caps, step 0, references, known commands; role skills in a `roles` folder: frontmatter, name, caps), `lint_skills` (default targets and the user's caps), `mentions(body)` (the command words of each `harness` code span or fenced line), `install(agents, root=, home=, cli_name=, yes=, source=)` → `InstallResult(entries, diffs)` with `needs_yes` (each agent's skills folder once: claude `.claude/skills`, codex and antigravity `.agents/skills`; globally `~/.claude/skills`, `~/.agents/skills`, `~/.gemini/config/skills`; a skill folder swapped in whole; one that differs is replaced only with `yes`, else its unified diff is returned), `install_skills` (the repo containing a path, or the home folder), `rename_cli(text, name)` (command prefixes in code spans and fenced lines only).
- `jobs`: detached job workers (SP3 spec decision 33). `spawn` (`python -m super_harness.worker <args>`, new session, `runtime/logs/<name>.log`), `start` (spawn and save the record), `alive` (live pid and fresh heartbeat), `heartbeat`, `forget` (own pid only), `exited` (`worker.exited` with `job`, `ok: false`, `reason`), `await_event` (the first matching journal event after a cursor; a synthetic `worker.exited` once the worker is gone; None at the timeout), `take_slot` (polls every 5 s, heartbeating), `died` (free the slot, journal "worker died"). `COMPACT` is the compaction job's id; plan reviews use the plan id.
- `calls.call(paths, provider, request, next_log)` → `Called(request, result, usage)`: the retry rules every CLI call shares (a timeout retries once; a schema error, and an empty turn whose actions were denied, get one repair turn on the session; `denied(result)` words it); `calls.again`, `repair`, `failure`, `plus` and `step_timeout` serve ticket steps too.
- `steps.run_job(ticket_id, project=, steps=)` → `JobEnd(status, reason)`: the step loop of SP3 spec §5. Per step: flags and caps under the project lock (`workflow.before`), the agent (`agents.pick`), a slot (`waiting_slot` while queued), the session (reused per role and provider; claude ids chosen before the call), the prompt, one adapter call, a commit with trailers after editing steps (agent commits folded by `reset --soft`), then Handoff or Findings, Log, tokens, session, `step.end`, routing (`workflow.after`) and a store commit under the lock. `steps=N` pauses after N steps. Errors: `timeout` retries once; `schema` gets one repair turn on the session; `rate_limit` falls back (`fallback_on_rate_limit`) or waits as `waiting_quota` until `retry_after` (15 minutes when unknown); `auth` fails with "sign in to <cli> interactively"; others fail with the log path. A failing commit hook gets one repair turn. A ticket the user moves mid-step keeps its status; the result is dropped. A dead worker's `running` call gives its session back (`recover_session`). A retried new claude session resumes once claude reported it or it timed out; one that never started is forgotten, so the next run starts afresh. `steps.fail_ticket(paths, slug, id, reason)` fails a running ticket; `fail_job` serves the worker.
- `calls.call(paths, provider, request, next_log)` → `Called(request, result, usage)`: a timeout retries once (a new claude session the CLI reported, or that timed out, is resumed), a schema error gets one repair turn on the session, anything else returns; `again`, `repair`, `failure`, `plus` and `step_timeout` serve `steps` too.
- `controls.run_tickets(ids, steps=, project=, by=)` → `RunResult(started, skipped)`: under the project lock, a live worker, the status (`in_queue/ready` or `in_process/failed|stalled|paused`), a pause, `touches` overlap, the first step, the agent (`NeedsSetup` when nothing usable) and a slot (`slots.reserve`) are checked; a claim creates or reuses the worktree (under `repo-<slug>.lock`), sets step and status, starts `python -m super_harness.worker` (`spawn_worker`) and writes its record. Resuming a stalled ticket clears its stall streaks and plan-review rounds. An approve step waits for `harness approve` without a worker. A network-less codex sandbox → `NeedsSetup`.
- `controls.approve_ticket`, `park_ticket` (deferred while a worker runs), `stop_ticket` (SIGTERM, SIGKILL after 10 s, then failed "stopped"), `pause`, `resume`.
- `merging.merge_ticket(id, project=, by=)` → `Merged(id, project, commits, base)`: from `awaiting_merge` or `branch_ready`, under the project lock and `repo-<slug>.lock`: rebase in the worktree (a conflict writes a finding and sends the ticket to `in_queue/ready` at `implement` with loop + 1, or to `needs_approval` at the loop cap, exit 1), `git merge --ff-only` in the main working tree (refused when dirty or off base), remove the worktree and branch, `done/merged`, dependents turn ready. `merging.merge_if_clean` serves `merge.mode: auto` (called after the project lock is released).
- `waiting.wait(project, timeout=, poll_s=)` → `WaitResult(events, idle, timed_out)`: the first call per scope reports the open gates (its cursor saved first); later calls report gate events from the journal after the scope's cursor (`ticket.needs_approval|stalled|failed|awaiting_merge|merged`, moves into `done/`, and `plan.reviewed` as `kind: plan`), `idle` when nothing in scope runs (a running plan review counts), or `timed_out`. Reviewed plans awaiting approval are open gates. `waiting.check_workers(paths, fix=)` fails the tickets of dead workers (gone pid or heartbeat older than 2 minutes) "worker died" and drops dead plan-review and compaction jobs (`jobs.died`); `dead_workers` lists their records; `ping` records the conductor. `next` checks workers and pings; `doctor` reports dead workers and marks them with `--fix`.
- `changes.ticket_changes(id, diff=, project=)` → `Changes(id, project, ref, changes, diff)`: one `Change(path, added, removed, loop, step, model, commit)` per file and commit, from the `Harness-*` trailers, on the ticket branch or (once merged) the base branch. `changes.attach_command(id, role=, project=)` → `Attach(..., command)`: `cd <worktree> && <the CLI's resume command>`.
- `lifecycle`: `step_status` (the `status.names` sub-status), `status_event` (the journal event of a status, with `status`, `loop`, `loop_max`, `reason`), `progress_of` (moved from `queue`), `progress_for` and `apply_progress` (workflow progress to and from a ticket and its state), `pid_alive`, `DEAD_AFTER_S`.
- `slots.reserve`: a claim's check and queueing under one lock.
- `tickets.refresh_queue` (was private): turn queued tickets ready or blocked to match their dependencies.
- `prompts`: step instructions, `new_prompt` (role, step, Goal, Scope, Acceptance, Handoff, Findings, diff stat inline), `resumed_prompt` (Findings for work steps; Handoff and diff stat for review steps), `repair_prompt`, `handoff_text` (redacted, 15 lines), `findings_text`, `log_line`, `output_kind`, `profile`, `role_skill` (`skills.role_text`: project `roles/<role>/SKILL.md`, then `defaults/roles/`, then the package; the body without frontmatter), `plan_review_prompt` (the plan inline; a new session also gets the newest DECISIONS entries, a resumed one the Review log), `review_log_lines`, `compact_prompt`.
- `reviews` (SP3 spec decisions 14, 28 to 30): `conductor_provider(by)` (`--by`, else claude under `CLAUDECODE=1`), `choose_reviewer(settings, conductor, detect)` → `(Pick, warning)` (a named `plan.reviewer`; else the plan-reviewer chain without the conductor's provider, then any other usable provider, then the conductor's own with a warning), `review_plan(plan_id, project=, by=, timeout=)` → `ReviewRound(id, project, round, max, verdict, findings, reviewer, warning)` with `used_up` (attach to a running round, reprint a round with its verdict, or choose the reviewer, mark the plan `in_review`, start the job and wait for its `plan.reviewed`; `NeedsUser` once the rounds are used up, `WaitTimeout` while it runs on), `run_review(plan_id, project=)` (the `plan-review` worker's round: read-only in the repo, a slot, the reviewer session resumed per plan and provider, round, verdict, session and Review log written, `plan.reviewed` journaled; a failed call or a plan changed meanwhile journals `worker.exited` instead), `fail_review`.
- `compaction` (SP3 spec decision 31): `compact_memory(timeout=)` → `memory.Compaction` (start the `compact` job or join it, then wait for `memory.compacted`; `NeedsSetup` when the compactor cannot run, `UserError` when the job fails, `WaitTimeout`), `start_background(paths)` (from `workspace.remember` once MEMORY.md passes its cap), `run_compaction()` (the worker's job: `memory.compactor`, read-only in `memory/`, a new session, a slot; `memory.apply_compaction` checks and writes), `fail_compaction`.
- `agents.pick(settings, role, status, skip=)` → `Pick(role, provider, model, fallback)`: the role's `cli`, then each fallback, first usable; `NeedsSetup` naming the install or sign-in step when none is. `agents.detector(paths)` detects each provider once; `agents.problem(provider, status)` says why one cannot run.
- `providers.check_providers(paths)` → `ProviderCheck(provider, users, blocking, message)` for each provider that enabled agents, their fallbacks or the compactor need (all scopes) and that is missing, signed out or unsupported (`blocking` when a role or the compactor is left with no usable provider), plus a warning for a claude login other than claude.ai unless `providers.claude.allow_api_key`; scopes with invalid settings are skipped. Detection goes through `adapters`.
- `providers.cli_clash()`: a warning when the first `harness` on PATH is not super-harness (its `--version`), naming `hrn` and `--cli-name hrn`; `doctor` reports it.
- `providers.trust_notice(paths, slug, repo)`: a warning when the repo ships `.claude/settings.json` hooks or `.mcp.json`, once until those files change (digest in `runtime/trust.json`).
- `projects.adopt(path)` → `AdoptResult`: merges a real `.harness/` folder by uuid and archives the original.
- `workspace`: `resolve_slug` (the named project, else the registered project containing the current folder), settings `settings_yaml`/`setting`/`settings_problems`, memory `remember` (starts compaction once MEMORY.md passes its cap)/`recall`, `context` → `Context(memory, project, process, gates)` (MEMORY.md, PROCESS.md headings, open gates) and `open_gates` → `OpenGate(id, sub_status, title)` items.
- `records`: `scope`, `locate_plan`, `locate_ticket` (ids are store-unique; `project` narrows the search), `taken_ids`, `project_tickets`, `project_plans`, `load_plan`/`load_ticket` (schema errors become `UserError`), `document` → `Document(project, path, meta, sections, text)`, `describe` (one line per validation error, with a "did you mean" for unknown fields and a quoting hint for YAML text read as a mapping), `one_line`, `record` (journal the events, then commit).
- `plans`: `new_plan`, `save_plan`, `show_plan`, `approve_plan`, `reject_plan` → `PlanResult(id, project, status, sections, review_skipped)`; approval needs a passing round or used-up rounds, a quick plan, `plan.review_max: 0`, or `skip_review`; a failed round with rounds left names the next step.
- `tickets`: `add_tickets` → `Batch(plan, project, tickets=[NewTicket(id, key, title, status)])`, `show_ticket` → `Document`, `list_tickets`/`find_tickets` → `TicketLine(id, project, status, importance, title)`; without a project they cover the project here, else every project.
- `tickets.move_ticket` → `Moved(id, project, before, after, ready, blocked)`; `tickets.set_fields` → `Updated(id, project, fields, status)` for the `SETTABLE` fields.
- `status.board(project=None)` → `Board([ProjectStatus(project, folders, statuses, gates)])`: every registered project unless one is named.
- `queue.next_tickets(project=None)` → `Queue(runnable, held_back, blocked, running, gates, paused)`: `runnable` holds `NextTicket(id, project, importance, step, provider, title)` in start order (`provider` is `shell` or `user` when the step needs no session); `held_back` maps each waiting ready ticket to its reason. `queue.progress_of(settings, ticket)` → `workflow.Progress`.
- Errors are `model` errors and carry their exit code.

## Invariants

- Registry changes happen under `runtime/locks/registry.lock`; project, plan and ticket changes under `runtime/locks/<slug>.lock`, then journal events, then a store commit.
- Every state change ends with a store commit (`harness: <command> <slug>`).
- Adopt deletes nothing: the original folder and every losing copy end up in `projects/<slug>/archive/adopted-<stamp>/`.
- `ticket add` validates the whole batch (schema, keys, references, cycles, workflows) before writing any ticket; a ticket is `ready` only when every dependency is merged or closed (`done/branch_ready` keeps dependents blocked).
- Queued tickets stay consistent: after any move or `depends_on` change each `ready`/`blocked` ticket is re-derived from its dependencies; `parked` is left alone; `in_process` needs every dependency merged or closed; a move to `done` clears the ticket's `step`, while parked or requeued tickets keep it and resume there.
- `ops` never imports `cli` or `ui`.
