# SP13 Watch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** every worker visible in its own terminal tab, one live dashboard per loop, desktop notifications at gates, at no model-token cost.

**Architecture:** `ops.terminals` builds tab-opening commands per terminal; a viewer registry in `runtime/viewers` keeps one tab per key; `controls` and `loops` open tabs when they start a worker or a loop; `ops.watch.board` gathers the dashboard from `progress`, `activity`, leases, slots and the journal; `ops.notify` runs from `records.record`.

**Tech Stack:** Python 3.12+, Typer, rich (already locked through Typer; declared directly), pytest with the fake CLIs.

**Spec:** `docs/superpowers/specs/2026-11-07-sp13-watch-design.md`

## Global Constraints

- No daemon; no model call for monitoring; a failed tab open or notification never fails the caller.
- `KENGASH_WATCH=off` disables tabs and notifications; `tests/conftest.py` and `ops.evals._env` set it.
- Hard rule 2: each module change updates its `docs/modules/<module>/README.md` in the same commit.
- Text output stays within 5 lines for status commands; `--json` everywhere.

## Review Focus

1. Two `kengash run` calls for one ticket within a second: one tab, not two.
2. A terminal command that hangs or is missing: `run` still returns at once with the printed command.
3. Tests, evals and CI never open a tab or send a notification, even with `DISPLAY` set.
4. `logs --watch` on a ticket parked or failed for good, then merged by the user: the tab ends.
5. A dashboard over projects with no running worker, a broken settings file, or an empty journal.
